# Temperature and Thermal Subsystem Troubleshooting Runbook

**Runbook ID:** THM-RB-001  
**Version:** 1.0  
**Subsystem:** Thermal Control  
**Application:** Satellite Telemetry Anomaly Triage Copilot  
**Data Type:** Synthetic telemetry for prototype demonstration

## 1. Purpose

This runbook provides troubleshooting guidance for identifying and investigating abnormal temperature telemetry readings.

It helps operators understand possible thermal anomalies, validate temperature sensor readings, investigate related subsystem measurements, and identify when further investigation is required.

This document is intended for an educational prototype using synthetic satellite telemetry. It is not an approved spacecraft operating procedure.

## 2. Subsystem Overview

The thermal control subsystem helps maintain spacecraft components within their required operating temperature ranges.

Spacecraft components may experience heating and cooling due to:
- Solar radiation.
- Heat generated by electronic equipment.
- Battery and power subsystem operation.
- Heat transfer between spacecraft components.
- The spacecraft's external thermal environment.

Thermal monitoring helps identify unusual temperature behaviour that may affect spacecraft equipment.

### 2.1 Important Telemetry Parameters

| Parameter | Description | Unit |
| :--- | :--- | :--- |
| Battery Temperature | Temperature measured near the battery | °C |
| Electronics Temperature | Temperature of electronic equipment | °C |
| Instrument Temperature | Temperature of scientific or onboard instruments | °C |
| Internal Temperature | Temperature measured inside the spacecraft | °C |
| Thermal Control Status | Available status of thermal control equipment | Status |

The prototype should use only the temperature parameters configured in its telemetry simulator.

### 2.3 Battery Temperature Ownership

Battery temperature may appear in both the Battery and Thermal runbooks, but it is considered from different subsystem perspectives:
- **Battery runbook (BAT-002):** Investigates battery temperature together with battery voltage, current, state of charge, and electrical-power behaviour.
- **Thermal runbook (this runbook):** Investigates temperature behaviour across spacecraft components, comparisons between thermal sensors, and available thermal control status.

When an event includes both battery electrical behaviour and temperature behaviour, the copilot may retrieve evidence from both runbooks. It must preserve each runbook's context and must not treat the overlap as duplicate or contradictory guidance.

## 3. Anomaly Identification

### 3.1 THM-001: Sudden Temperature Rise

**Description:**

A temperature measurement increases significantly compared with its recent readings.

**Possible indicators:**
- Rapid temperature increase.
- Repeated temperature increases.
- Temperature exceeding configured upper limits.
- Multiple temperature sensors showing similar changes.

**Possible causes:**
- Increased electrical power consumption.
- Abnormal equipment operating conditions.
- Thermal control system issue.
- Unexpected environmental heating.
- Temperature sensor malfunction.
- Telemetry measurement error.

### 3.2 THM-002: Unexpected Temperature Drop

**Description:**

A temperature reading decreases unexpectedly compared with its normal trend.

**Possible indicators:**
- Sudden temperature decrease.
- Persistent low-temperature readings.
- Temperature outside configured lower limits.
- Differences between related temperature sensors.

**Possible causes:**
- Thermal control issue.
- Unexpected environmental cooling.
- Changes in equipment operating conditions.
- Sensor malfunction.
- Telemetry transmission problem.

### 3.3 THM-003: Temperature Sensor Inconsistency

**Description:**

Two or more related temperature sensors report significantly different behaviour.

**Possible indicators:**
- One sensor increases while another remains stable.
- One sensor reports an unexpected temperature.
- A sensor remains frozen.
- Sudden jumps in temperature readings.

**Possible causes:**
- Sensor malfunction.
- Different physical thermal conditions.
- Sensor calibration issue.
- Telemetry processing error.
- Missing or delayed measurements.

### 3.4 THM-004: Continuous Temperature Fluctuation

**Description:**

Temperature readings repeatedly increase and decrease instead of following the expected trend.

**Possible indicators:**
- Repeated temperature spikes.
- Rapid fluctuations.
- Unusual variations over consecutive readings.
- Different behaviour between related sensors.

**Possible causes:**
- Changing equipment operating conditions.
- Thermal control instability.
- Sensor noise.
- Measurement or transmission errors.

## 4. Telemetry Data Validation

Before diagnosing a thermal anomaly, validate the quality of the available measurements.

### 4.1 Missing Data Check

Check whether temperature measurements are missing.

**Investigation:**
- Identify null or missing values.
- Check timestamps for gaps.
- Verify whether the temperature sensor has stopped updating.

**Expected result:** Missing readings should be marked as unavailable, not replaced with zero.

### 4.2 Frozen Sensor Check

Check whether a temperature sensor repeatedly reports the same value.

**Investigation:**
- Compare consecutive readings.
- Calculate how long the value has remained unchanged.
- Compare with other available temperature sensors.

**Expected result:** Suspiciously constant readings should be flagged for sensor verification.

### 4.3 Valid Range Check

Check whether temperature readings fall within configured engineering limits.

**Examples:**
- Readings outside configured sensor limits should be flagged.
- Impossible or malformed measurements should be identified.
- Sudden values inconsistent with the configured sensor range require investigation.

Do not use invented universal spacecraft temperature limits.

### 4.4 Cross-Signal Consistency Check

Compare related measurements.

**Examples:**
- Compare battery temperature with electronics temperature.
- Compare temperature trends with battery voltage and current.
- Compare multiple temperature sensors when available.
- Examine thermal control status if available.

**Expected result:** Suspicious inconsistencies should be marked for further investigation.

**Important:** A sensor disagreement does not automatically mean that one sensor is faulty. Different spacecraft components can legitimately operate at different temperatures.

## 5. Investigation Procedures

### 5.1 Procedure for Sudden Temperature Rise

1. Identify the timestamp when the temperature increase began.
2. Examine temperature readings before and after the event.
3. Determine whether the increase is gradual or sudden.
4. Compare readings from other temperature sensors.
5. Examine battery voltage and current.
6. Review thermal control status if available.
7. Check for missing, frozen, or invalid sensor readings.
8. Identify simultaneous anomalies in other subsystems.
9. Review historical thermal incidents.
10. Identify possible explanations supported by the evidence.

### 5.2 Procedure for Unexpected Temperature Drop

1. Identify when the temperature decrease began.
2. Examine the temperature trend.
3. Compare related temperature sensors.
4. Check whether the readings are within configured limits.
5. Examine the equipment operating state if available.
6. Review thermal control status.
7. Check sensor integrity flags.
8. Identify whether the decrease is persistent or temporary.

### 5.3 Procedure for Temperature Sensor Inconsistency

1. Identify the sensors reporting different readings.
2. Compare their timestamps.
3. Check whether the sensors measure different physical locations.
4. Examine consecutive readings from each sensor.
5. Check for frozen or missing measurements.
6. Compare related subsystem telemetry.
7. Determine whether the difference can be explained by normal operating conditions.
8. Flag unresolved inconsistencies for operator investigation.

### 5.4 Procedure for Continuous Temperature Fluctuation

1. Identify when the repeated temperature fluctuations began.
2. Examine the affected sensor's readings over the relevant time interval.
3. Determine whether the fluctuations are isolated or appear across multiple sensors.
4. Compare timestamps and sampling intervals to check for timing or data-ordering issues.
5. Review thermal control status if available.
6. Compare the temperature trend with battery voltage and current, where relevant.
7. Check for missing, frozen, malformed, or delayed measurements.
8. Determine whether the fluctuations persist or occur only briefly.
9. Flag unexplained or persistent fluctuations for operator investigation.

## 6. Recommended Investigation Guidance

Based on retrieved evidence, the application may recommend that the operator:
- Review temperature trends over the relevant time interval.
- Compare readings from related sensors.
- Examine associated battery and power measurements.
- Check the thermal control status if available.
- Verify the quality and completeness of temperature telemetry.
- Review historical thermal incidents.
- Consult approved mission-specific thermal documentation.

Recommendations must remain investigative.

The application must not generate or execute spacecraft thermal control commands.

## 7. Escalation Conditions

Flag the incident for operator attention when:
- Temperature remains outside configured limits.
- Temperature continues increasing or decreasing unexpectedly.
- Multiple sensors indicate a similar abnormal trend.
- Temperature anomalies occur alongside power anomalies.
- Sensor disagreement prevents reliable assessment.
- Telemetry quality problems prevent a reliable thermal assessment.

Mission-specific escalation thresholds must come from approved mission documentation.

### 7.1 Prototype Triage Severity Guidance

The prototype may attach a qualitative triage label to help explain the evidence. These labels are not spacecraft mission severity classifications and must not be derived from invented universal temperature limits.

| Prototype label | Guidance |
| :--- | :--- |
| Low | A brief or isolated deviation with no corroborating abnormal measurements and no identified data-quality concern. |
| Medium | A repeated or persistent temperature deviation, or an event supported by another relevant measurement. |
| High | A persistent or worsening deviation, multiple related sensors showing abnormal behaviour, or a temperature event accompanied by other subsystem anomalies. |
| Undetermined | Available telemetry is missing, invalid, inconsistent, or insufficient to assess the event reliably. |

The label must be based on the observed event duration, trend, supporting signals, and data quality. If evidence is insufficient, use Undetermined rather than guessing. The operator retains responsibility for assessing urgency.

## 8. Cross-Subsystem Relationships

### 8.1 Temperature and Battery Relationship

**Example:**
- Battery temperature increases.
- Battery voltage decreases.
- Battery current changes.

**Possible interpretation:** The measurements may indicate an abnormal battery or power operating condition.

Further investigation is required before identifying a root cause.

### 8.2 Temperature and Attitude Relationship

**Example:**
- Electronics temperature increases.
- Attitude measurements show unexpected changes.

**Possible interpretation:** Both events may share an operating condition or may be independent.

The system should investigate the timestamps and available supporting telemetry.

Correlation does not prove causation.

## 11. Limitations and Safety Notes

- This runbook is designed for a synthetic telemetry demonstration.
- No universal spacecraft temperature limits are specified.
- Mission-specific limits must be obtained from approved engineering documentation.
- Possible causes must not be presented as confirmed failures.
- Different components may legitimately have different temperatures.
- Sensor integrity checks cannot conclusively determine whether an anomaly is genuine.
- LLM recommendations must be grounded in retrieved runbook evidence.
- No autonomous spacecraft control or command execution is permitted.
